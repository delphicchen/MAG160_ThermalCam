# 雙鏡頭立體測距計畫（2026-10-12）

> **2026-10-12 結論：小米 14T Pro 不可行。** `isSessionConfigurationSupported` 回 true、兩路都有影格，
> 但 HAL 同一時間只開一顆感光元件，另一路給全黑影格（時間戳與另一路相同）：
> - 主 + 超廣角實體串流，zoom 1.0 / 0.95 / 0.9 / 0.8 / 0.7 / 0.6：超廣角全黑（mean 0）。
> - 只開超廣角：正常（已確認是超廣角視角、有桶狀變形）。
> - 邏輯串流 + 超廣角：邏輯串流也切到超廣角，兩路同一顆。
> - 主 / 超廣角逐幀交替（repeating burst）：兩路 0 影格，接著 HAL 報 CAMERA_ERROR。
> 先後切換取像需數百 ms，手持平移誤差遠大於 2.1 cm 基線的精度，不可行。
> 探測程式（`camera/StereoProbe.kt`、抽屜「雙鏡頭測試」）已於 2026-10-12 移除（使用者決定不留雙鏡）。
> 下一步改走熱像 ↔ 可見光三角測量（方案 B，基線約 0.19 m，見 `PLAN_TRIANGULATION.md`）。


## 目標
用手機後鏡頭的**主鏡頭 + 超廣角**做立體視覺，量出十字線處（之後可擴充為逐區）的
**公尺物距**，取代不可靠的對焦讀值，餵給現有的融合視差補償（`FusionCalibration`）。

取代先前的方案 D（單眼深度模型，見 `PLAN_DEPTH.md`，已放棄）。

## 這支手機（Xiaomi 14T Pro）的條件（`dumpsys media.camera`）
| | 主鏡頭（實體 ID 6） | 超廣角（實體 ID 3） |
|---|---|---|
| 邏輯相機 | 0（physicalIds = 6, 3） | 同左 |
| 焦距 | 6.57 mm，fx 2742 px @4096×3072 | 1.91 mm，fx 1705 px @4000×3000 |
| 對焦 | AF，UNCALIBRATED | **定焦**（minimumFocusDistance 0） |
| 相對位置 | 參考點 | (−0.88, −21.12, 0) mm → **基線約 2.1 cm** |
| 旋轉 / 畸變 | 回報 identity / 0 | 回報 identity / 0（應是設計值，非逐台校正） |
| 同步 | sensorSyncType = APPROXIMATE | |

長焦（ID 2）回報位置 0（未填），不使用。系統沒有 DEPTH_OUTPUT。

## 精度預估
統一換到超廣角解析度（640 寬 fx ≈ 273 px；1280 寬 ≈ 546 px），基線 2.1 cm，比對 0.25 px：
0.5 m ±1 %、1 m ±4 %（1280：±2 %）、2 m ±8 %（±4 %）。換算熱像疊合誤差，1 m 內 < 1 熱像像素。

## 分次執行
1. **S1 支援探測**（✅ 2026-10-12：14T Pro 可同時串流兩顆實體鏡頭）：抽屜按鈕「雙鏡頭探測」。停掉融合相機 → 開邏輯相機，兩個
   ImageReader 分別綁實體 ID（`OutputConfiguration.setPhysicalCameraId`）→
   `isSessionConfigurationSupported` + 實際收 3 秒影格 → 紀錄每路影格數、時間戳差、
   各實體鏡頭參數；灰階影像對存 Pictures/MagViewer/stereo（PNG），紀錄存 Download/MagViewer。
2. **S2 離線驗證**（電腦，Python）：用 S1 的影像對做校正平行化 + 沿極線比對，
   確認視差方向、無窮遠偏移量級、近距離可行性。
3. **S3 App 內測距**：`RgbCamera` 改 Camera2 雙串流；中央視窗沿極線比對 → 公尺物距，
   新增物距來源「雙鏡頭」；一次性「對遠方歸零」校正旋轉偏差。
4. **S4（選配）逐區**：分格測距處理斜面與前後景。

## 風險
- 小米可能不開放第三方 App 同時串流兩顆實體鏡頭 → S1 會直接回答。
- 超廣角定焦，近距離（< 0.4 m）可能模糊；畸變未回報，需自行估。
- 素面牆沒有紋理，無法比對 → 退回手動物距。

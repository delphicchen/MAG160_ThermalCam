# MAG-Mx NUC Raw-Map Decode (pure-numpy rebuild research)

Status: GAIN fully decoded bit-exact. ref/bp sources identified. offset proven DERIVED (not a direct map).
Method that works: unicorn memory-read hook on cali region + poke oracle (see below). Env `testenv`
has unicorn 2.1.4. lib symlink: /tmp/apk_x/lib/armeabi-v7a/libcoresdk.so -> reverse_eng/apk_decompile/.../libcoresdk.so.

## Cali layout (this device)
- File: 128B header + 48 maps of 160x120 u16 @ offset 1024 (each 38400B).
- ONLY maps 0-8 (block0) and 27-35 (block1) are valid/used. Blocks 2-5 (anchors >=29108) read NOTHING -> output zero.
  So real FPA working range = 9000..29000 (block0@9564, block1@19330).
- Valid blocks are NON-CONTIGUOUS: block0 maps 0-8, block1 maps 27-35. The "6 blocks x 8 maps" guess is WRONG.

## Build readout architecture (proven)
All 5 fields are direct readouts of the maps with a per-block (base_map, off) transform, EXCEPT offset which is COMPUTED.
Pixel index q = r*160+c (0..19199). HALF = 9600.
- first half (q<9600), second half (q>=9600).
- Continuous flat array FM = cali maps reshaped (48*19200,), indexed WITHOUT per-map mod (natural spill into next map).
- Gain seg s, block b:
    pe = (base_b + 2s)*NPIX + 2*q[:HALF] + off_b
    po = (base_b + 2s + 1)*NPIX + 2*(q[HALF:]-HALF) + off_b
    gain[q,s] = FM[pe] (first half), FM[po] (second half)
  * block0: base_b = 2,  off_b = 64       -> maps 2..8 (continuous spill)
  * block1: base_b = 30, off_b = -12736   -> maps 30..36 (continuous spill)
  => GAIN IS BIT-EXACT (max|diff| = 0.0) for both blocks.

## Other fields (source maps found via poke; transform not yet calibrated)
- ref  (19200,): block0 <- map0 ;  block1 <- map28 (poke map0@0 moves ref; map28@0 moves block1 ref? verify)
- bp   (19200,2): block0 <- maps 0 AND 1 (both move bp); block1 <- maps 28 AND 29.
- offset (19200,3): NOT a direct map read. DERIVED:
    offset[:,s] ~= 8192 - ((ref * gain[:,s]) >> 15)   (single-seg max|d|~345, all-seg~575; refine T/K/rounding).
  Implication: a from-scratch numpy rebuild computes offset arithmetically from ref & gain; no map lookup needed.

## Apply pipeline (ALREADY bit-exact, validated earlier)
v = (raw - ref) >> 1
s = first segment with v <= bp[i,s]   (nseg=3)
out = clamp( (v * gain[i,s]) >> 12 + offset[i,s], 0, 65535 )
shift=12, nseg=3.

## How to extract remaining details (reproducible)
1. memory-read hook (unicorn UC_HOOK_MEM_READ) on cali region during build_at_fpa -> reveals which maps are
   read per anchor, and stride/offset of access.
2. poke oracle: build, poke one map pixel +1000, rebuild, see which output pixel/field moved. Maps q->(map,px).
3. For ref/bp: calibrate per-block off_b the same way gain's off_b was found (poke a grid, fit q = f(p)).

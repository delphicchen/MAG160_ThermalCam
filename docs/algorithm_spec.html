2 · USB 協定（PROTOCOL.md 摘要 + 已證實細節）

2.1 端點（interface 0，全 bulk）

端點方向用途
0x03OUT命令（8B：<cmd:u32><param:u32>；部分命令 4B 只有 cmd）
0x82IN命令 ack／遙測。每條命令寫入後必讀
0x81IN影像流（38456 B/幀週期）
0x84IN校正檔下載流（GetCaliFile 用）
鐵律：寫 EP 0x03 的每一條命令（含 StartTransferImg/StopTransferImg）必須接著讀一次 EP 0x82 ack， 否則韌體卡死、裝置自動重新列舉。

2.2 命令字

命令值說明
GetParameter10x6BB6B66Back ≥32B；off20=W(u32)、off24=H、off28=fps
GetParameter20x6BB6B66C初始化序列的一部分，讀 ack 即可
GetCaliInfo0x6BB6B66Fack 20B（含檔案大小 0x001C53A0）
GetCaliFile0x6BB6B6704B 命令；ack off4=u32 大小；之後從 EP 0x84 分塊（≤0x80000）讀取
SetShutter0x6BB6B672param 0=關快門(FFC)、1=開
StartTransferImg0x6BB6B6734-byte 封包 + 讀 ack（5F B5 B5 5B…）
StopTransferImg0x6BB6B674同上

2.3 影像幀格式（EP 0x81）

period = 28(hdr) + 160·120·2(payload) + 28(tail) = 38456 bytes
hdr[0..3] = 1B B1 B1 1B (magic)   hdr[+4] = 幀號 u32
tail[0..3] = 1C B1 B1 1B          tail[+8] = FPA 感測溫度 u32（anchor-A 單位）
payload = LE u16 ×19200，row-major，未校正原始計數
幀間無對齊保證 → 掃 magic 切幀；上電前 ~10 幀近飽和，丟棄

連線順序：StopXfer → drain 0x82 → GetParam1(重試至 ≥32B) → GetParam2 → GetCaliInfo → clear_halt(0x81) → 起 reader thread → StartXfer(+ack)。 每次連線都應下載該台相機自己的 mag_cali.bin（原廠 App 同路徑）；不同體可能不同。

2.4 FFC（快門校正）程序

SetShutter(0) → sleep 400ms → 收 N≈4 幀平均 = ffcRef(H×W float)
→ SetShutter(1) → sleep 400ms

ffcRef 是「快門暗場」＝整條影像鏈的 offset_ref 定義域（見 §4）。建議依 FPA 漂移 ≥120 或時間觸發 auto-FFC。

3 · 校正檔 mag_cali.bin（1,856,416 B）

3.1 檔頭

off 0   : magic 0x5AA50003 (parser 也接受 0x5AA50004)
off 4/8 : W=160, H=120
off 12  : 6      （錨點數）
off 16  : 3      （nseg，piecewise 段數）
off 20  : 8      （shift=12 相關參數欄）
off 24  : -50000 （輻射參數 ctx[0x7750]）
off 28  : 1024   （資料起點 dataoff）
off 36  : 表A[6] = {9564, 19330, 29108, 34111, 39244, 49091}   ← FPA 錨點（感測溫度單位）
off 60  : 表B[6] = A − 500
off 84  : 表C[6] = {8041, 9311, 10588, 11301, 12075, 13642}（語意未完全確認）
off 108 : {32,32,32,32,32}

3.2 資料區（1024 起）：48 張 160×120 u16 map

= 6 溫度 block × [ gain_map_0, gain_map_1, ref_0 .. ref_5 ]   (每張 38400 B)
block b ↔ 錨點區間 [A[b], A[b+1])
live FPA 直接索引 block（frame tail+8 與表 A 同單位）

檔尾另有 12,192 B 附表（成對 u16：hi≈13000、lo≈2700，內部含 160-entry 週期結構）—— parser 原樣複製到工作緩衝 bufA+0x1C2380；推定為原廠輻射定標附表，本開源鏈不使用（我們以兩點常數取代，見 §5）。

3.3 由 cali 展開 NUC 表（原廠 build 鏈，Unicorn 模擬已復現）

parser sub_424d0(ctx, path)   → 解析至 bufA（6.3MB 工作區）
sub_3a7f8(ctx, mode=0, 0)     → prepare：bracket FPA(ctx[0x38]) vs 表A → section idx + 權重 w
sub_3a7f8(ctx, mode=1, 2)     → build：斷點內插 → bufB、gain/offset 建立(sub_3bc54) → bufC
                                並填 radLUT ← planck_luts[6]（100% 驗證）

表佈局（nseg=3, shift=12）：
 breakpoint[i,s] = bufB_i16[2i+s]           s∈0..1
 gain[i,s]       = bufC_u16[2i + 2·N·s]
 offset[i,s]     = bufC_u16[2i + 2·N·s + 1]
開源做法：離線以模擬器在 FPA=9000..29000（步距1000）預展開 21 組表存成 factory_nuc_grid.npz{fpa,ref,breakpoints,gain,offset,nseg,shift}，執行期最近鄰取表。 實測與該台實機即時下載的 cali 重建結果 bit-identical。

4 · 影像處理鏈（逐式）

4.1 出廠 NUC apply（bit-exact，源自 sub_45ca4）

v        = (raw[i] − offset_ref[i]) >> 1
s        = 第一個滿足 v ≤ breakpoint[i,s] 的段（否則最後段）
out[i]   = clamp( ((v · gain[i,s]) >> 12) + offset[i,s],  0, 65535 )
  • offset_ref 必須是快門域的 ffcRef（實測 §Phase-E：零飽和、段內漂移 ±20 counts/min）。 使用 cali 內建 ref 會造成 ~35% 像素飽和——不要用。
  • grid 取表用「最近鄰」；跨段切換會有 ±1000 counts 位準跳 → 由 §4.3 的 trim 吸收。 不要混合內插表格（實測引入隨溫度線性漂移），不要做 levelBaseline 移除（破壞輻射定標）。

4.2 壞點修補（顯示品質用，選用）

FFC 後以靜態場學習 per-pixel 閾值清單（|value−鄰域中位數|>門檻者記錄），執行期以十字鄰域中位數替換； 另對單幀做即時偵測。只影響顯示與 min/max 統計之前可選擇性套用。

4.3 Level-lock trim（漂移鎖定，等效原廠 k,b/shutter-corr 機制）

狀態：trim(float, 初始0)、lastGridIdx、lastFfcRef

每次輸出前： out' = out + trim

觸發時機（grid 表翻段 或 ffcRef 更新）：
  old = 以「舊配置」算出的中位數(out)
  new = 以「新配置」算出的中位數(out)
  trim += clamp(old − new, ±1000)
  更新 lastGridIdx / lastFfcRef

語意：假設場景在切換瞬間不變，把表格切換/FFC 造成的系統跳動折入加法微調。 夾限 ±1000 與原廠 sub_3d228 內 cmp r1,#0x3E8 的 ±1000 clamp 一致。 實測：段內穩定度由 ±3000 counts 跳動降至 ±10。

4.4 時間降噪（選用）

IIR：disp = disp·α + new·(1−α)，α≈0.5–0.7；只在顯示域，測溫域用單幀或短平均。

5 · 測溫（輻射測溫鏈）

5.1 Planck LUT 反查（bit-exact，源自 sub_3f970）

資產：recon/planck_luts.npy = 8 條 × 646 格 int 輻射曲線（自 .rodata 抽出）
slopeLUT[i] = 2²⁴ // (radLUT[i+1] − radLUT[i])    ← 韌體同款倒斜率表

U_from_radiance(li, rad):
    idx = clamp(searchsorted(radLUT[li], rad, 'right')−1, 0, 644)
    U = idx·4096 − 150000 + ((slopeLUT[idx]·(rad − radLUT[idx])) >> 12)
°C = U/1000 − 273.15          (U 單位 milli-Kelvin)

5.2 LUT 選擇 —— 逆向結論：lut_idx = 6

以 Unicorn 載入真實 libcoresdk.so、餵真實 mag_cali.bin 跑完 prepare+build(mode1,param2)， dump .bss radLUT@0x29d700 共 646 格，與 planck_luts.npy row 6 = 100% bit-identical。 即：韌體為此相機選的就是第 6 條曲線。非擬合猜測。

5.3 出廠常數（一次性兩點標定，2026-08-26 實測）

radiance = a·out + ba = 42.7562, b = −119255.6
lut_idx6
標定点 1鋁合金墊（環境反射 ≈室溫 26°C）↔ out=8378
標定点 2臉部皮膚 34.5°C ↔ out=8610
敏感度face±1°C → a 變動 0.3%（mid-range ±0.03°C）

外推檢查：out=9000→48.5°C、11000→116°C、14000→208°C（Planck 加速形狀正確）。 若日後換相機個體或重標定：只需兩個已知溫度目標重解 (a,b)；lut_idx 可用模擬器流程重驗。

5.4 原廠環境修正（未啟用的完整版，供日後參考）

FixPara 啟用時（MAG_SetFixPara → ctx[0xb8]=1）：
  τ_total = Tao · f2 · ε            (Tao 由 sub_3a2d0 從距離/濕度/溫度算出)
  R(T_obj) = ( L_meas − (1−τ_total)·R(T_reflected) ) / τ_total
  U = LUT_inverse(R(T_obj))         （兩次 646 格查表 + 夾限 0x285）
參數區 ctx[0xbc..0xe0]：ε∈(0,1)、T_amb≥−25、距離>0、濕度等 → CorrectionPara

手持近距應用下 ε≈1、τ≈1，修正量小；故 v1 不實作，介面保留。

10 · 補幀 / 解析度提昇可行性評估（現代手機）

10.1 硬體基準

平台級別NPUGPU備註
Dimensity 9200 / S8 Gen2+30–60 TOPS(INT8)~2–4 TFLOPS FP32NNAPI/GPU delegate 成熟
中階（7 系/6 系）5–15 TOPS<1 TFLOPSCPU 仍可跑輕量 SR

10.2 解析度提昇

方法成本(160×120→320×240)品質結論
Bicubic / GPU bilinear~0（GPU 合成順手）軟糊保底
ESPCN-v2 2×/4×（已驗證）CPU 2執行緒 ~3.7 ms/幀+2.4 dB vs bicubic採用；NNAPI INT8 再加速
FSRCNN-s / ESPCN-INT8 NNAPI<2 ms（NPU）近似次期優化
Real-ESRGAN 級 GAN>200 ms/幀（手機）過度幻覺紋理✗ 熱成像不適合（假細節誤導判讀）

熱成像注意：SR 屬顯示增視；溫度標記必須取樣自原生網格再映射，不得對 SR 後像素測溫。

10.3 補幀（15 fps → 30/60 fps）

方法可行性風險
簡單時間混疊（blend 兩幀）✅ 便宜（~0.2 ms）移動物拖影；測溫延遲半幀
光流補幀（RAFAN/FILM 級）⚠️ 手機可跑但 160×120 上光流被噪聲主導熱圖噪聲大，向量場不可靠；運算不成比例
提高實際幀率韌體上限 ~15 fps（GetParameter 回報）—
建議：顯示以 60 Hz Compose 直渲染 + SR，視覺流暢度已足； 補幀僅在「錄影」場景用 blend 式 2× 插值（標註非測溫幀）。優先序：SR(NNAPI INT8) ≫ 補幀。
